# Сборка и размещение

## Готовые файлы

```bash
npm ci
npm run build
npm run verify:media
```

Результат находится в `out/`. Настройки `output: "export"`, `images.unoptimized: true`
и `trailingSlash: true` сохранены. Node.js нужен для сборки, а публикация текущего сайта
использует только статические файлы.

## Beget

1. Соберите сайт локально или в сборочном окружении.
2. В панели хостинга определите каталог сайта для нужного домена.
3. Сохраните резервную копию содержимого этого каталога.
4. Загрузите **содержимое** `out/`, включая `_next/`, `media/`, `index.html` и страницы ошибок.
5. Настройте HTTPS в панели и проверьте главную страницу, изображения, видео, якоря и формы.

Не загружайте `src/`, `assets/originals/`, `node_modules/`, конфигурацию окружения и историю Git.
Настройки домена и доступ к хостингу не менялись в рамках реорганизации.

## Cloudflare

Существующие команды `deploy` и `deploy:preview`, `wrangler.jsonc` и каталог `out/` сохранены.
Согласно исходной документации проекта, Workers Builds публикует `main` в production,
а остальные ветки — как preview. Фактические настройки проверяются в панели Cloudflare.
Не добавляйте второй автоматический деплой поверх уже настроенного.

## Формы и билеты

`NEXT_PUBLIC_FORM_ENDPOINT` — публичный адрес обработчика форм. Он подставляется **при сборке**;
после изменения нужно пересобрать и повторно выложить сайт. Секретные токены в него не помещают.
Внутри статического экспорта нет серверного обработчика заявок.

`SALES_OPEN` и `TICKETS_URL` находятся в `src/content/event.ts`. Текущие значения сохранены:
продажи выключены, ссылка пуста. Реорганизация не подключает эквайринг, рассылку или хранение заявок.
